\paragraph{Open algorithm RFCs.}
\begin{itemize}
\item expected\_improvement\_transition: Credible probability gating was too conservative at p=.65 and too permissive for late h=5 at p=.56; expected improvement should trade benefit and loss continuously.
\item cap\_or\_uncertain\_late\_large\_horizon: Run 1618 showed h=5/bucket=8 caused final-eval collapse after a strong 250k checkpoint; larger horizon switches late in training need a general uncertainty gate.
\item sparse\_hifi\_chaos\_validation: Clean Dense-RHS already has a non-inferior Sparse-HiFi winner, and the 120k fallback recovered to 640.40; the campaign should now test the same family under chaos against the no-RHS chaos reference.
\item clean\_plus2\_sparse\_hifi\_parallel: The formal clean goal is now to beat no-RHS by 2\%; run two distinct Sparse-HiFi clean attempts in parallel under the max-2-GPU policy.
\item learner\_aware\_virtual\_update\_query: Current Dense-RHS mostly tests transition policy over existing diagnostics; it does not estimate whether a candidate horizon improves the learner after update. Add sparse virtual TD-MPC2 update probes for candidate horizons and score post-update validation loss/planner utility.
\item shadow\_horizon\_training\_stats: Gather better horizon evidence during ordinary training by computing shadow loss/target statistics for nearby horizons from the same replay batches, without changing deployed horizon or adding environment interaction.
\item deployment\_utility\_posterior: Replace one-shot query score switching with a posterior over observed post-switch training improvement so horizon changes are justified by downstream learner utility rather than immediate candidate rollout return alone.
\item paired\_fixed\_seed\_query\_eval: Verify or enforce paired reset seeds and matched perturbations across candidate horizons so query return differences have lower variance and are attributable to horizon choice.
\end{itemize}
